# CA Lab — PKI на Docker

Лабораторный удостоверяющий центр (CA) на базе Ubuntu + OpenSSL, запущенный в Docker. Генерирует и подписывает сертификаты, ведёт базу для отзыва (CRL).

## Структура проекта

```
ca-docker/
├── Dockerfile              # образ: Ubuntu + openssl, живой контейнер (tail -f /dev/null)
├── scripts/                # скрипты запускаются вручную внутри контейнера
│   ├── 00-init-ca.sh       # создать Root CA + базу + конфиг (один раз)
│   ├── 01-new-request.sh   # создать ключ + CSR для сущности
│   ├── 02-sign-cert.sh     # подписать CSR, запись уходит в базу (db/index.txt)
│   ├── 03-revoke-cert.sh   # [Участник 2] отозвать сертификат
│   ├── 04-gen-crl.sh       # [Участник 2] сгенерировать CRL
│   └── 05-check-revocation.sh  # [Участник 2] проверить статус (OK / revoked)
└── pki/                    # bind mount: /pki внутри контейнера = эта папка на Windows
```

## Структура `pki/`

```
pki/
├── ca/
│   ├── private/
│   │   └── ca.key          # приватный ключ CA — НИКОГДА не передаётся, не публикуется
│   └── certs/
│       └── ca.crt          # сертификат CA — публичный, им все проверяют подписи
│
├── users/                  # каждая сущность (сервер, клиент, тестовый юзер) — своя папка
│   └── <имя>/
│       ├── <имя>.key       # приватный ключ сущности
│       ├── <имя>.csr       # запрос на подпись (CSR)
│       └── <имя>.crt       # подписанный сертификат
│
├── db/                     # база данных CA — кто выпущен, кто отозван
│   ├── index.txt           # реестр: статус (V/R), серийник, Subject, дата отзыва
│   ├── serial               # следующий серийный номер для новых сертификатов
│   ├── crlnumber            # номер версии следующего CRL
│   └── newcerts/           # копия каждого подписанного сертификата по номеру
│
├── crl/
│   └── ca.crl               # список отозванных сертификатов (генерируется 04-gen-crl.sh)
│
└── config/
    └── ca.cnf                # конфиг для всех команд openssl ca (revoke, gencrl, sign)
```

## Правило: что публично, что секретно

| Файл | Доступ | Где используется |
|---|---|---|
| `ca/private/ca.key` | Только внутри CA | Подписывает CSR, отзывает сертификаты |
| `ca/certs/ca.crt` | Публичный, раздаётся всем | Клиенты и сервер проверяют им подписи |
| `users/<имя>/<имя>.key` | Только у владельца сущности | TLS-рукопожатие на своей стороне |
| `users/<имя>/<имя>.crt` | Публичный | Предъявляется другой стороне при подключении |

## Быстрый старт

```cmd
docker build -t ca-image .
docker run -d --name ca-container -v %cd%\pki:/pki ca-image
docker exec -it ca-container bash
```

Внутри контейнера:

```bash
/scripts/00-init-ca.sh              # один раз — создать CA
mkdir -p users/server
/scripts/01-new-request.sh server   # создать ключ + CSR
/scripts/02-sign-cert.sh server     # подписать
```

## Для Участника 2 (отзыв / CRL)

Зависимости уже готовы при условии, что `00-init-ca.sh` был выполнен:
- `config/ca.cnf` — общий конфиг, использовать через `-config /pki/config/ca.cnf`
- `db/index.txt`, `db/serial`, `db/crlnumber`, `db/newcerts/` — база CA
- Любой сертификат для отзыва лежит в `users/<имя>/<имя>.crt`

Архитектура папок менять не нужно — только добавлять файлы в `crl/` (через `04-gen-crl.sh`) и дописывать записи в `db/index.txt` (через `03-revoke-cert.sh`).
